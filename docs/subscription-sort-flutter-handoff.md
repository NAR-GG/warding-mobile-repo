# 구독 설정 화면 정렬 — 플러터 작업 요청서

구독 설정 화면의 선수 목록을 포지션순과 이름순(A–Z) 중에서 골라 볼 수 있게 하는 작업입니다.
서버 API는 바꾸지 않습니다. 정렬 축이 되는 값(`role`, `playerName`)이 이미 응답에 들어 있어서
앱에서 정렬만 하면 됩니다.

| | |
|---|---|
| 백엔드 작업 | 완료 (PR #366 배포됨, PR #367 머지 대기) |
| API 변경 | 없음. `sort` 파라미터도 없습니다 |
| 앱 수정 파일 | 2개 + l10n |
| 예상 | 0.5일 |

## 배경

지금 선수 목록의 순서는 서버가 정합니다. 포지션(탑 → 정글 → 미드 → 원딜 → 서포터) 다음 이름
오름차순이고, 앱은 받은 순서대로 그립니다. 앱에는 정렬 코드가 없습니다.

이 순서 자체는 유지합니다. 유저가 특정 선수를 이름으로 찾을 때 포지션 그룹을 훑어야 하는 게
불편해서, 이름순(A–Z) 선택지를 추가하는 작업입니다.

포지션이 비어 있어 정렬에서 맨 뒤로 밀리던 선수 18명(Fenrir, Painter, Deft, Rascal 등)은
백엔드에서 채웠습니다. 지금 구독 가능 선수 102명 전원이 포지션 값을 가집니다.

## 먼저 읽어주세요

1. **"가나다순"이 아니라 A–Z입니다.** 구독 가능 선수 102명 중 한글 닉네임은 0명입니다.
   화면에 보이는 이름(`playerName`)은 전부 로마자(Faker, Zeus, Deft)라서 정렬 결과는 알파벳순입니다.
   한글 본명으로 정렬하려면 `real_name`이 필요한데, 102명 중 한글 본명이 있는 선수는 75명입니다.
   나머지 27명은 정렬 축이 비고, 화면에는 닉네임이 보이는데 순서는 본명 기준이 되어 유저에게
   "정렬이 깨졌다"로 읽힙니다. **본명 기준 정렬은 하지 말아주세요.** UI 라벨도 "가나다순"보다
   "이름순"이 정확합니다.

2. **`_pageSize`를 200으로 올리는 건 PR #367 배포 후에만 유효합니다.** 서버가 `size`를 100으로
   자르고 있었고 구독 가능 선수는 102명입니다. 상한 300으로 올리는 PR이 머지 대기 중입니다.
   배포 전에 200을 보내면 서버가 조용히 100으로 깎아서 2명이 다음 페이지로 넘어갑니다.
   그러면 정렬한 목록 뒤에 무한 스크롤로 2명이 나중에 붙어서 순서가 흔들립니다. 배포 여부를
   확인하고 올려주세요.

3. **`role` 값은 대소문자를 무시하고 비교해주세요.** DB 표기는 `Top`, `Jungle`, `Mid`, `ADC`,
   `Support`입니다. 서버도 비교 전에 대문자로 올립니다(`PlayerRoleOrder`). 앱에서 `'Mid'`와
   문자열 동등 비교를 하면 표기가 바뀔 때 조용히 "미상"으로 떨어집니다.

4. **구독 토글 직후 순서가 깨지는 버그가 이미 있습니다.** `_applyPlayerToggle`이 새 구독을
   `_subscribedPlayers` 끝에 그냥 붙입니다(`subscription_settings_viewmodel.dart:195`).
   지금은 정렬 기준이 없어서 눈에 안 띄지만, 정렬을 넣으면 구독을 누른 선수만 맨 밑에 붙어서
   바로 보입니다. 이번 작업에서 같이 고쳐주세요.

## API

두 엔드포인트 모두 그대로 씁니다. 경로는 `api_config.dart:159`, `:177`에 이미 있습니다.

| 엔드포인트 | 페이징 | 서버 정렬 |
|---|---|---|
| `GET /api/mobile/me/player-subscriptions` | 없음. 구독 전체를 한 번에 | 포지션 → 이름 |
| `GET /api/mobile/me/player-subscriptions/available-players` | `page`, `size` (상한 300) | 포지션 → 이름 |

정렬에 쓸 응답 필드는 두 개입니다.

| 필드 | 값 | 비고 |
|---|---|---|
| `role` | `Top` / `Jungle` / `Mid` / `ADC` / `Support` | 현재 구독 가능 선수 전원 채워져 있음 |
| `playerName` | 로마자 닉네임 | 전원 로마자. 중복 없음(DB UNIQUE) |

`teamCode`, `teamName`도 응답에 있지만 이번 작업에서는 쓰지 않습니다.

## 작업 내용

1. `subscription_settings_viewmodel.dart:24` — `_pageSize`를 100에서 200으로 올립니다.
   (PR #367 배포 확인 후)

2. 같은 파일에 정렬 모드를 추가합니다. `enum PlayerSortMode { position, name }`, 기본값은
   `position`입니다. `subscribedPlayers`, `availablePlayers` getter가 현재 모드로 정렬한
   리스트를 반환하게 하고, 모드 변경 시 `notifyListeners()`를 호출합니다. 서버 재조회는 하지
   않습니다.

3. `_applyPlayerToggle`(`:185`)의 append를 정렬 삽입으로 바꿉니다. 2번의 comparator를 그대로
   재사용하면 됩니다.

4. `subscription_settings_screen.dart` — 정렬 칩을 추가합니다. 선수 목록이 두 군데(구독중인 선수
   섹션 `:123`, 전체 목록의 선수 탭 `:136`)라 정렬 모드는 하나로 공유하고 칩도 하나만 둡니다.
   `NarChip`을 쓰면 `player_select_sheet.dart`의 사용 예를 그대로 참고할 수 있습니다.

5. `app_ko.arb`, `app_en.arb`에 라벨 두 개를 추가합니다. 한국어는 "포지션순", "이름순"을
   제안합니다.

## 정렬 규칙

포지션순은 서버와 같은 순서를 씁니다. 서버 구현은 `PlayerRoleOrder.java`입니다.

1. `TOP` → `JUNGLE` → `MID` → `ADC` → `SUPPORT`
2. 알 수 없는 값과 null은 맨 뒤
3. 같은 포지션 안에서는 이름 오름차순(대소문자 무시)

이름순은 `playerName` 오름차순 하나입니다. 대소문자를 무시하고 비교해주세요.

지금 데이터에는 포지션이 빈 선수가 없지만, 백오피스로 선수를 새로 추가하면 다시 생길 수
있습니다. 2번의 "맨 뒤" 규칙은 남겨주세요.

## 검증

- 포지션순에서 Fenrir(원딜)와 Painter(정글)가 각자 포지션 그룹에 들어갑니다. 목록 맨 뒤에
  있으면 백엔드 배포가 안 된 상태입니다.
- 이름순에서 전체 목록을 끝까지 스크롤해도 순서가 유지됩니다. 중간에 새 항목이 뒤에 붙으면
  `_pageSize`가 서버 상한에 걸린 것입니다.
- 구독중인 선수 섹션에서 선수를 구독/해제한 직후에도 순서가 유지됩니다.
- 검색어를 넣은 뒤에도 선택한 정렬 모드가 유지됩니다.

## 하지 않는 것

- 팀별 정렬·그룹핑. 솔랭 계정만 있는 선수는 서버가 팀을 null로 내려서 "소속 없음" 그룹이
  커집니다. 이번에는 제외합니다.
- 서버 `sort` 파라미터 추가. 정렬 축이 이미 응답에 있고, 서버에 넣으려면 60줄짜리 네이티브
  UNION 쿼리의 `ORDER BY`를 분기시켜야 합니다.
- 본명(`real_name`) 기준 한글 정렬. 위 "먼저 읽어주세요" 1번을 참고해주세요.
