# Spec: e2e 기준선 (구현을 모르는 블랙박스 e2e)

줄기: [webview-migration](../webview-migration/spec.md)
상태: **설계 중.** 웹뷰 이관 여부와 상관없이 진행한다.
warding-docs: 해당 없음 (개발 쪽 테스트 인프라다)

## Summary

"이관해도 e2e가 똑같아야 한다"를 판정하려면 비교할 기준선이 있어야 하는데, 지금은 없다.

- e2e는 `integration_test/app_smoke_test.dart` **1개**다. 스플래시를 지나 로그인 화면이 뜨는지만 본다.
- Flutter `integration_test`는 위젯 트리 안만 본다. **WebView 안은 볼 수 없어서** 웹판 화면을 테스트할 수 없다.
- API 주소가 `lib/config/api_config.dart`에 `https://api.nar.kr`로 고정돼 있다. 테스트가 prod를 피할 방법이 없다.
  2026-10-31 화면 캡처 중 prod 실계정의 선수 구독이 지워진 일이 실제로 있었다.
- `Semantics(identifier:)`를 쓰는 곳이 0곳이다. 테스트가 화면 요소를 안정적으로 집을 수단이 없다.

이 가지는 **구현을 모르는 블랙박스 e2e**를 만들고, 지금 Flutter 앱으로 전부 통과시켜 기준선으로 고정한다.
같은 시나리오 파일이 나중에 웹판 화면에서도 그대로 돌아야 한다.

이관을 안 하더라도 가치가 있다. Shorebird 패치는 심사 없이 바로 사용자에게 나가는데, 지금 그 앞을 막는
e2e는 스모크 1개뿐이다. 이 기준선이 `patch-deploy.yml`과 `release-deploy.yml`의 게이트가 된다.

## Requirements

1. **시나리오는 구현을 모른다.** 위젯 타입이나 Dart 코드가 아니라, 화면 식별자와 보이는 텍스트로만 요소를 찾는다.
2. **prod에 절대 쓰지 않는다.** e2e 빌드가 `api.nar.kr`를 바라보면 앱이 시작하자마자 실패해야 한다.
3. **결과가 결정적이다.** 같은 시나리오는 언제 돌려도 같은 데이터, 같은 화면이 나온다.
4. **동등성은 세 가지로 판정한다.** 화면 단언, 앱이 보낸 API 요청 기록, 앱이 보낸 분석 이벤트 기록.
5. **같은 시나리오 파일**이 화면 모드 flutter와 web 양쪽에서 통과해야 그 화면의 스위치를 켤 수 있다.
6. 기존 릴리즈·패치 게이트에 붙는다. 새 게이트를 따로 만들지 않는다.

## Design / Approach

### 테스트 계층

e2e 하나에 모든 걸 맡기지 않는다. 계층마다 잡는 것이 다르다.

| 계층 | 무엇 | 도구 | 이관 시 역할 |
|---|---|---|---|
| L1 규칙 | 화면에 들어가는 순수 규칙 (솔랭 분류, 순위표 템플릿 판정 등) | 공유 JSON 케이스 파일 + Dart test / Vitest | 같은 케이스 파일을 Dart와 TS 테스트가 함께 읽는다. 입력과 기대값이 한 벌이다 |
| L2 계약 | 목 서버 응답이 실제 API 스키마와 맞는지 | `docs/openapi_spec.json` 검증 | 목 데이터가 실서버와 어긋나는 것을 막는다 |
| L3 e2e | 사용자 흐름 (이 문서의 중심) | Maestro + 목 서버 | Flutter판·웹판 동등성 판정 |
| L4 실서버 스모크 | 실제 dev 서버와 붙여 소수 흐름 | Maestro + dev 서버 + 테스트 계정 | 목이 못 잡는 계약 변화를 잡는다 |
| L5 운영 비교 | 단계별 공개 지표 | Mixpanel, Sentry | 줄기의 "단계별 공개" 참고 |

### 도구: Maestro

| 후보 | 판단 |
|---|---|
| **Maestro** | 접근성 트리로 화면을 조작하는 블랙박스 도구다. Flutter 화면과 WebView 안을 같은 YAML로 다룰 수 있다. CLI는 오픈소스라 GitHub Actions에서 무료로 돈다 |
| Flutter `integration_test` (지금) | WebView 안을 못 본다. 이관 판정에 쓸 수 없다 |
| Patrol | 네이티브 조작은 되지만 테스트가 Dart 위젯 코드에 묶인다. 구현을 모르는 테스트가 아니다 |
| Appium | 가능하지만 설정과 유지 비용이 크다 |

### 테스트 데이터: 목 서버가 기본, dev 서버는 스모크만

결정적 결과(요구사항 3)와 상태별 화면(솔랭 중, 월즈 스위스 등)을 마음대로 만들려면 목 서버가 필요하다.
dev 서버는 데이터가 계속 바뀌어서 기준선 비교에 쓸 수 없다.

- **목 서버**: 표준 라이브러리만 쓰는 작은 HTTP 서버 하나다. 프레임워크를 들이지 않는다.
  - 시나리오별 응답 파일: `e2e/fixtures/<시나리오>/<METHOD> <경로>.json`
  - 시나리오 전환: 흐름 시작 시 `POST /__scenario {"name": "..."}` (Maestro `runScript`의 http 호출)
  - 요청 기록: 앱이 보낸 모든 요청을 쌓아 두고 `GET /__log`로 꺼낸다. 요구사항 4의 "API 요청 기록"이다.
  - 분석 이벤트 기록: `POST /__analytics`로 받는다(아래 앱 변경 3).
- **응답 파일 만드는 법**: dev 서버 응답을 한 번 녹화하고, 상태별로 손으로 고친다. 10/31 화면 모음
  (솔랭 카드 상태, 순위표 템플릿 4종 등)이 상태 목록의 출발점이다.
- **응답 파일 검증(L2)**: CI에서 응답 파일을 `docs/openapi_spec.json` 스키마로 검증한다. `sync-api-docs`로
  스펙이 바뀌었는데 응답 파일이 안 맞으면 실패한다.

### 앱 변경 (최소)

전부 Dart 변경이라 스토어 릴리즈 없이 나갈 수 있다. e2e 빌드에서만 켜진다.

1. **`API_HOST` dart-define.** 기본값은 지금처럼 `https://api.nar.kr`다. `api_config.dart`의 `host`만 바꾼다.
2. **prod 차단.** `E2E=true`인데 `API_HOST`가 prod면 `main()`에서 바로 예외를 던진다.
3. **분석 이벤트 기록.** `E2E=true`면 `Analytics`가 Mixpanel 대신 목 서버 `/__analytics`로 보낸다. 웹판도 브리지로
   `Analytics`를 거치므로(줄기 Decisions) 같은 지점에서 기록된다. 분석 이벤트 회귀도 같이 잡힌다.
4. **로그인 주입.** 소셜 로그인은 자동화하지 않는다. `E2E_ACCESS_TOKEN`이 있으면 시작 전에 보안 저장소에 넣는다.
   목 서버는 아무 토큰이나 받는다. dev 서버 스모크는 테스트 계정 토큰을 CI 시크릿으로 넣는다.
5. **화면 식별자.** 시나리오가 실제로 집는 요소에만 `Semantics(identifier:)`를 붙인다. 전체에 일괄로 붙이지 않는다.
   이름은 `<탭>.<화면>.<요소>`다(예: `community.post.like`). 웹판도 같은 문자열을 쓴다.
6. **고정해야 하는 값.** Mixpanel 피처 플래그, 광고 응답, 현재 시각(솔랭 경과 시간 등)을 e2e에서 고정한다.
   시각은 `E2E_NOW` 같은 값으로 주입한다.

### 동등성 판정

흐름 하나를 돌리면 세 가지 결과가 나온다.

| 결과 | 판정 방법 |
|---|---|
| 화면 단언 | Maestro `assertVisible` 등. 통과/실패 |
| API 요청 기록 | 메서드, 경로, 정규화한 본문. 저장된 기준 파일과 비교한다 |
| 분석 이벤트 기록 | 이벤트 이름과 정규화한 속성. 저장된 기준 파일과 비교한다 |

- **지금 (기준선 단계)**: 현재 Flutter 앱으로 돌린 기록을 `e2e/golden/<흐름>.api.json`, `.analytics.json`으로
  저장한다. 이후 실행은 이 파일과 달라지면 실패한다. 기준을 바꾸려면 갱신 명령으로 다시 뽑고 PR에서 diff를 리뷰한다.
- **이관 단계**: 같은 흐름을 `PAGE_MODE=<화면>:web`으로 돌린 기록이 같은 기준 파일과 일치해야 한다.
  어쩔 수 없이 다른 항목은 허용 목록 파일에 사유와 함께 적는다.
- 정규화: 시각, 요청 ID, 순서가 의미 없는 배열은 비교 전에 지우거나 정렬한다.
- 스크린샷은 사람이 나란히 보는 용도로만 남긴다. 픽셀 비교를 게이트로 쓰지 않는다. 폰트와 렌더링이
  Flutter와 웹에서 원래 다르기 때문이다.

**P0: 모든 릴리즈·패치와 화면 스위치 전환의 게이트다.** 15개 안팎으로 유지한다.

| ID | 탭 | 흐름 | 주로 잡는 것 |
|---|---|---|---|

| C2 | 공통 | 로그인 콜드 스타트 → 홈 | 토큰 전달 |
| C3 | 공통 | 탭 5개 전환, 같은 탭 다시 누르면 맨 위로 | 탭 셸 |
| H1 | 홈 | 순위표 리그 전환, 펼치기, 토너먼트 대진 전환 | 상태 분기 |
| H2 | 홈 | 솔랭 카드 → 선수 페이지 | 진입 경로 |
| H3 | 홈 | 쇼츠 카드 → 전체화면 피드 → 닫기 | WebView 속 WebView |

**P1: 매일 밤 돈다. 게이트는 아니다.**
- 상태 매트릭스: 솔랭 카드 상태별, 월즈 솔랭, 순위표 템플릿 4종, 빈 상태, 서버 오류(목 서버가 500 반환), 오프라인
- 한/영 전환, 온보딩(비회원, 완료 API는 목 서버로만 간다)
- L4 실서버 스모크: C2, K1(읽기만), M1을 dev 서버와 테스트 계정으로

### CI

| 언제 | 무엇 | 러너 |
|---|---|---|
| `release/*`, `patch/*` 태그 | P0 (iOS 시뮬레이터) | 지금 `e2e-release-check.yml`의 macOS 러너에 추가한다. `patch-deploy.yml`과 릴리즈 파이프라인은 이미 이 결과를 기다린다 |
| 매일 밤 | P1 + L4 | macOS(iOS), ubuntu + KVM(Android 에뮬레이터) |
| 웹판 배포 (이관 단계) | 해당 화면 P0를 `PAGE_MODE=web`으로, 웹 미리보기 URL을 바라보게 | web-app 가지에서 정한다 |

- 실패하면 지금 있는 `escalate` 잡(실패 로그 분석 → 문서 초안)을 그대로 쓰고, Maestro 스크린샷과 기록을 첨부한다.
- 기존 `app_smoke_test.dart`는 Maestro P0가 2주 동안 안정적으로 통과한 뒤 지운다.
- 불안정한 흐름은 재시도 1회까지만 허용한다. 그래도 흔들리면 격리 목록으로 빼고 이슈를 연다. 게이트를 끄지 않는다.
- Android 에뮬레이터 실행은 첫 웹판 스위치(커뮤니티) 전까지만 붙이면 된다. K2의 사진 첨부가 Android에서만 깨지는 지점이다.

실제 시간은 시뮬레이터에서 흐름을 안정시키는 데서 결정된다.

## Decisions

- 도구는 Maestro다.
- 기준선은 목 서버로 만들고, dev 서버는 야간 스모크에만 쓴다.
- 동등성은 화면, API 요청 기록, 분석 이벤트 기록 세 가지로 판정한다. 픽셀 비교는 게이트로 쓰지 않는다.
- 소셜 로그인은 자동화하지 않고 토큰을 주입한다.
- 화면 식별자는 시나리오가 쓰는 곳에만 붙인다.

## Out of scope

- 성능 측정(스크롤 프레임, 첫 로딩 시간). 이관 단계에서 별도로 다룬다.
- 픽셀 비교 게이트.
- PR마다 e2e 실행. macOS 러너 비용 때문에 지금처럼 릴리즈·패치 때만 돈다.
- 백엔드(nar) 테스트.

## Open questions

스파이크(0단계)에서 확인할 것:
- [ ] Maestro `id:` 선택자가 Flutter `Semantics(identifier:)`를 iOS·Android 양쪽에서 집는가.
- [ ] Maestro가 WebView 안 요소를 어떤 선택자로 집는가. HTML `id`가 잡히는지, 아니면 `aria-label`·텍스트를
      써야 하는지에 따라 웹판의 식별자 규칙이 정해진다. Android는 `androidWebViewHierarchy` 설정도 확인한다.
- [ ] iOS 시뮬레이터·Android 에뮬레이터에서 `http://localhost` 목 서버 접근이 ATS·cleartext 정책에 막히는가.
      막히면 예외 설정이 네이티브 변경이라 스토어 릴리즈가 필요한지 확인한다.
- [ ] 홈 위젯 데이터(S2)를 테스트에서 어떻게 확인할지. 위젯 저장소를 읽는 디버그 경로가 필요할 수 있다.
- [ ] 푸시 탭(E1)을 시뮬레이터 푸시로 재현할 수 있는가. 안 되면 같은 라우팅 함수를 딥링크로 태운다.

팀과 정할 것:
- [ ] dev 서버의 e2e 전용 테스트 계정 (L4용).
- [ ] 기준 파일 갱신 PR의 리뷰어 (분석 이벤트가 바뀌면 Mixpanel 담당자가 봐야 한다).
